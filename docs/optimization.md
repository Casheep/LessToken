# 本地优化验证（2026-10-20）

这是第一版原型的固定文本量结果，尚未发布或替换已安装的插件。完整模型任务对照先测得 0.90%，修正实际往返后提升到 24.79%，仍未达到目标，详见 [完整任务验证](e2e-validation.md)。下表不代表当前全部改动或实际聊天的节省率。

## 改动

- `lt_search` 增加 `before` / `after`（0..40，默认仍为 1 / 2）。调用者可以一次获取定位结果和所需原文，重叠窗口合并，保留命中行号。没有增加新的 MCP 工具。
- 日志支持折叠连续、完全相同的 2..16 行块，明确保留重复次数和顺序。没有去除时间戳、合并近似文本或使用小模型总结。包含诊断关键词的块保持展开，并补充 `traceback` / `panic` 保护。
- 搜索的行或窗口超出预览限制时明确标记 `clipped=true`，避免将截短片段当作完整证据。源文件不修改；可用较窄的原文读取或字节分页补查。
- 精简每次搜索重复返回的说明文字，保留统计、范围及完整性字段。

示例：

```json
{"query":"Store::stats","path":"src/core.cpp","before":2,"after":18}
```

## 测量方法和结果

使用固定提交 `a57b5fd` 的源码作为测试输入，冻结 10 项任务：4 项原文检索、2 项重复日志，以及不重复日志、测试失败、代码和 JSON 控制项。日志和数据是人工生成的固定样本，不代表真实用户使用频率。

旧版检索也只补读任务所需的精确范围，没有以读取整个文件或默认 100 行来扩大基线。新版必须返回完全相同的源码证据。测试脚本对字节一致性、诊断信息和完整原文恢复执行断言。

统计包含工具调用 JSON、返回文本，以及这批任务共计一份工具定义；新增参数的定义开销也计入。使用 `tiktoken 0.14.0` 的两种编码逐条计数，不使用字节数除以 4。

| 编码 | 原始文本参考 | 旧版插件 | 新版插件 | 相对原始参考减少 | 相对旧版减少 |
| --- | ---: | ---: | ---: | ---: | ---: |
| o200k_base | 9,957 | 7,695 | 5,931 | 40.43% | 22.92% |
| cl100k_base | 9,914 | 7,652 | 5,889 | 40.60% | 23.04% |

调用次数从 **14 次降至 10 次**。原始记录和样本/程序 SHA-256 见 [optimization-benchmark.json](optimization-benchmark.json)。随机生成的原文引用会导致重新测量时 token 数有小幅波动。

**“原始文本参考”是文本量对照，不是卸载插件后的实测。** 它保留旧版调用和工具定义，将日志、测试和 JSON 的返回内容替换为完整原文；代码和检索使用旧版的精确原文结果。不能把它解释成真实订阅额度或整个聊天消耗。

这批测试在工具文本层面达到约 40% 的目标。未计入模型推理、历史上下文重复、宿主封装、技能说明、缓存及订阅计量，也没有实际模型回答的端到端质量评测。前次本机累计的约 32% 是另一批记录的字节统计，不能与这里相加或直接对比。

## 质量与使用边界

20 项原生回归测试通过，覆盖精确窗口、默认行为、重叠/间隔/跨文件、命中上限、参数校验、路径约束、中文、长行、编辑后刷新、工具发现、日志重建、原文恢复、诊断保护、执行次数、stderr、退出码和存储失败回退。日志重建还覆盖固定随机种子的 40 组块宽度/重复次数组合。

主模型没有替换，也没有降低推理设置。这里验证的是输入证据和工具行为；不能据此承诺所有任务的智能或成功率绝不下降。调用者仍需检查 `complete`、`scan_complete` 和 `clipped`，在信息不足时补读原文。

## 复现

需要 C++20 编译环境和 Python。`tiktoken` 仅供开发测量，插件运行时不依赖它，也不会联网调用模型。编码数据首次获取可能需要网络。

先将旧提交 `a57b5fd` 编译到独立目录，保留旧版可执行文件，再构建当前分支：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build.ps1
python tests/optimization.py build/lesstoken.exe
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/verify.ps1
python -m pip install tiktoken==0.14.0
python scripts/benchmark_optimization.py --baseline PATH_TO_BASELINE_EXE --candidate build/lesstoken.exe --source-ref a57b5fd --output .research/optimization-benchmark.json
```

测试及测量均使用临时文件和独立 `LESSTOKEN_DATA`，不混入正在使用的插件统计。分支上的版本号仍沿用 beta.6；根目录 `PUBLICATION_MANIFEST.json` 保留已发布 beta.6 的历史校验值，不适用于这些未发布修改。正式打包前需要重新生成发布校验清单。
