# 完整任务 token 对照验收

2026-10-20，固定 12 项任务、24 个独立模型会话中，关闭插件的原生工具基线总用量为 **348,641 token**，新版为 **194,298 token**，合计减少 **44.27%**。新版通过 **12/12**，基线通过 **11/12**；两项 C++ 修复答案均经过真实编译和功能测试。

模型固定为 `gpt-6.1-sol`，推理档位为 `medium`，没有切换便宜模型或把推理工作交给弱模型。优化主要减少文件定位、重复补读和参数失败重试：在模型执行前，由本地程序为明确点名的文件提供完整证据；重复日志仅精确折叠，源码保持原文，JSON 保留键、值和数值写法。格式和字节问题保留原始格式，超预算或有歧义时交回正常工具。

## 方法与适用范围

- 两组使用相同样本、问题、模型、推理档位和执行权限；新会话独立状态，交替先后顺序。基线没有 LessToken MCP，新版同时可用原生工具、MCP 和提交提示词钩子。
- 记录成功终态的真实模型用量。总 token 为输入加输出，缓存输入已经包含在输入中，推理输出已经包含在输出中，不重复相加。不是输出字节压缩率，也不是订阅额度或费用节省率。
- 两组均使用与当前用户相同的 `danger-full-access` 执行档位。任务要求只读生成的样本，并校验每项前后文件哈希一致。此前受 CLI 原生命令策略阻止的尝试没有计入有效结果。
- 每项每组仅一次，未估计置信区间；12 项不能保证所有任务都省 40% 或所有回答质量相同。本次达到固定任务集约 40% 的工程验收目标。
- 模型评测仅启用提示词钩子；命令包装器另有本地校验。执行后钩子已从注册中移除，旧 `--post` 为无输出操作，避免错误地停止模型。
- 评测后增加格式敏感请求保护及执行后钩子修正。12 项提示词生成的模型证据与冻结版本一致，仅随机引用 ID 不同；对应哈希和逐项比较随报告保存。其余行为通过本地回归检查。

完整的脱敏计数、环境、功能判定和校验值见 [e2e-native-validation.json](e2e-native-validation.json)。原始模型记录留在忽略的 `.research` 目录，不公开个人路径和聊天内容。开发脚本默认只准备样本，显式 `--run` 才启动模型评测。
